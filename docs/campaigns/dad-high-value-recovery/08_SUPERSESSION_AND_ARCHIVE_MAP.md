# Supersession and Archive Map

This campaign reuses existing DAD authority and evidence. It does not silently
replace earlier plans, mark legacy roadmap phases incomplete, or create new
control planes.

## Relationship to existing plans

| Existing surface | Relationship | What this campaign reuses | What this campaign does not do |
|---|---|---|---|
| `roadmap/roadmap.yaml` | parallel, not superseded | validation discipline and human-gate evidence | It does not add a phase or reinterpret historical completion. |
| `docs/SELF_LEARNING_IMPROVEMENT_SYSTEM_PLAN.md` | narrowed execution overlay | SI-01–SI-05 evaluator discipline, bounded pilots, decay/retirement, one build + one pilot limit | It does not activate the broad self-learning system. |
| `docs/DAD_PORTFOLIO_AI_OPERATING_SYSTEM_PLAN.md` | reuse existing projections | cockpit Today list, workstream/session/recovery evidence, proposal-only boundaries | It does not create another queue or Git executor. |

| `docs/DAD_EXCEPTIONS_LAKE_BUILDOUT.md` | retain proven kernel | exception to fix to independent validation | It does not treat unvalidated clusters as learning. |
| `docs/orchestration-recovery/README.md` | historical reference only | recovered lessons and warnings | It does not reactivate inert recovered authority. |
| `docs/PR_BRANCH_LIFECYCLE_GOVERNANCE.md` | governing pattern | owner, next action, validation, escalation, no inferred deletion | It does not authorize branch cleanup. |
| Global `ACTIVE_WORKTREES.yaml` | external authority | ownership, hold, and disposition records | DAD reports cannot override or replace it. |

## Consolidation rules after the pilot

Consolidation is permitted only after the Phase 06 decision and a separately
approved implementation revision.

- Session, handoff, and lesson records may be projected into a task record plus
  optional learning delta only when lossless rebuild and backward compatibility
  are proven.
- Follow-through, lifecycle, and attention lists may share one read-only queue
  projection only when source ledgers remain authoritative and dedupe is tested.
- Worktree ownership remains global; DAD may mirror or report it, not fork it.
- Graphs remain rebuildable projections, not action or lifecycle authority.
- Every retired component gets a tombstone/pointer in the lifecycle registry;
  raw history stays immutable.

## Decision mapping

| Phase 06 decision | Required next artifact | Automatic action allowed? |
|---|---|---|
| `scale` | bounded follow-on plan for only successful workflow slices | No |
| `narrow` | retained-kernel manifest and explicit dormant list | No |
| `retire` | human-reviewed lifecycle/tombstone plan with rollback | No |
| `re-audit` | evidence-repair plan naming why the evidence was invalid | No |

The campaign ends at the decision. A follow-on build needs its own exact scope,
current digests, independent checker, and human approval.
