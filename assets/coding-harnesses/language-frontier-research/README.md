# Language Frontier Research

Candidate harness for turning Python, Rust, mixed-language, and future-language
discoveries into DAD assets without letting hype become doctrine.

Use this when a repo, agent, or research refresh finds a language feature,
crate, package, tool, codebase pattern, or AI-coding technique that might make
future agents write safer, faster, or easier-to-review code.

## Intake Rules

- Store pointer-only evidence: source URL or source ID, safe summary,
  applicability limits, and a validation idea.
- Route Python discoveries to the Python advantage assets, idiom cards, pytest
  orchestration harness, or coding tactics radar.
- Route Rust discoveries to the Rust buildout guide, Rust shadow parity harness,
  parser/scanner/fuzz candidates, or coding tactics radar.
- Route future-language discoveries to a candidate language row only after an
  official or reviewed source and a proof tool are named.
- Reject copied third-party docs, copied source blobs, private rows, secrets,
  raw logs, and benchmark claims without same-workload evidence.

## Frontier Questions

- What proof surface does the language or tool add: compiler, linter, type
  checker, test runner, fuzzer, profiler, package auditor, or runtime tracer?
- What concrete operation should an agent run or inspect before making the
  claim, and what safe proof output should be recorded?
- What pattern is AI likely to miss because it is underrepresented in generic
  examples but valuable in DAD repos?
- What local command would falsify the benefit?
- What repo contexts should avoid the tactic?

## Promotion Boundary

A frontier idea can become durable guidance only after screened source pointers,
local validation, applicability limits, and postflight or harness feedback.
This harness is the first-pass gate; it is not promotion authority.

## Refresh Prompt

Use `prompts/language-frontier-refresh.prompt.md` for weekly or monthly source
refreshes. It turns high-signal Python, Rust, mixed-language, and future-language
discoveries into a small candidate packet with source, safe summary, proof
surface, local falsification idea, AI-overlooked pattern, target DAD surface,
and rejection reason when needed.

The prompt exists because language research is tempting to overclaim. DAD wants
the boring useful part: executable proof surfaces and local harness cases that
make future agents better at reading, writing, running, and repairing code.
