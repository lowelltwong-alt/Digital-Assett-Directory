# Personal Hierarchical Agent Mesh

This is DAD's runtime-neutral adaptation of Lowell's active global personal
skill. The live global skill root remains source authority. This adaptation is
candidate reusable guidance; DAD may register and point to it but must not
install it, overwrite a runtime skill, or override repository-local policy.

## Trigger And Route

Activate at the start of every planning-mode turn. Activate when starting,
resuming, executing, or revising a plan, checklist, roadmap, handoff, or prior
decomposition. Outside formal planning, activate for material multi-step work.
Bias toward activation because routing is cheap; activation does not require
delegation.

Before implementation, emit or update one compact mesh block with:

- `mesh_revision` and `activation_basis` (`plan_mode`, `plan_execution`, or
  `material_work`);
- `delegation_decision` (`local_only`, `worker_checker`, `foreman`, `boss`, or
  `fable`) plus the positive signals, suppressors, and deterministic leaves;
- the source plan revision for execution or resumption;
- workstreams, dependencies, role ownership, write scope, and context slices;
- capability tier, effort, selection reason, and cheaper rejected route;
- independent checker, acceptance evidence, handoff, and stop conditions; and
- bounded fan-out, attempts, context, token, and wall time when exposed.

If subagents are unavailable, preserve the route as a checklist fallback. If
delegation costs more than the work, record `local_only` and retain the same
proof obligations.

## Expand Proportionally

Use deterministic tools first for exact facts, parsing, diffs, schemas, hashes,
and tests. Expand only as evidence earns it:

1. Use local execution for trivial, reversible, one-step, or deterministic work.
2. Use one bounded worker plus an independent checker for material leaf work.
3. Add a foreman for several non-overlapping workstreams, integration, or
   dependency management.
4. Add a boss only for unresolved material disagreement, load-bearing
   architecture, or high-consequence rulings.
5. Use Fable only through a named human gate for exceptional architecture or
   systemic unresolved disagreement.

Treat worker, checker, foreman, and boss as responsibilities, not status. Keep
writes non-overlapping and delegation depth bounded by the controlling runtime.
Allow evidence-backed upward and lateral challenge; a cheaper checker can catch
a more capable worker on exact facts.

## Route Capability And Effort

Resolve model names from current runtime capabilities and local policy. Use:

- Luna for bounded extraction, inventory, formatting, and exact checks;
- Terra for normal implementation, synthesis, planning, integration, and
  foreman work; and
- Sol for hard architecture, adversarial analysis, root cause, and unresolved
  high-consequence disagreement.

Select effort separately: low for crisp bounded work, medium for normal
multi-step judgment, high for ambiguity or integration, xhigh for exceptional
systemic complexity, and max only after a demonstrated xhigh evidence gap.
Ultra always requires explicit human approval for the exact attempt, regardless
of model tier. In Lowell's active global runtime,
`$subagent-peer-review-routing` remains authoritative for exact spawn, checking,
grading, and escalation gates. In other runtimes, apply the active repository or
runtime's canonical subagent and independent-review policy when it is stricter.

## Reconcile During Execution

For material work, use `$dad-manifest-graph-engineering` to persist the planning
mesh as a strict task-local manifest. At execution preflight, reload the exact
plan and mesh revision and reconcile every planned role and proof obligation.
Mark each role `reused`, `replaced`, `split`, `added`, `removed`, or `blocked`.
Append a new manifest revision whenever a material dependency, authority,
data-flow, architecture, privacy, schema, repository direction, risk,
capability, or proof obligation changes. Never let an execution worker approve
its own decomposition change or silently lose a planned lane.

## Preserve Authority And Efficiency

Send each agent only its contract slice, evidence pointers, checks, and relevant
prior defects. Cache reusable context by hash, bound retries, and downgrade work
when deterministic evidence proves a cheaper tier can satisfy the contract.
Never send secrets, private payloads, raw conversations, hidden reasoning, or
unnecessary source blobs. Agents produce candidate evidence; named humans retain
product, legal, security, privacy, data, release, budget, and exception authority.
