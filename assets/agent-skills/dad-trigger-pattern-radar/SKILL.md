# DAD Trigger Pattern Radar

Treat trigger signatures as reusable digital assets. Discover them continuously;
promote none from frequency, confidence, centrality, or model enthusiasm alone.

## Run the radar

1. Inventory immutable observations and coverage: task events, repo/worktree
   state, validation, handoffs, dependencies, dismissals, failures, and actions.
2. Read `references/TRIGGER_PATTERN_CONTRACT.md` and normalize candidates.
3. Match `references/TRIGGER_PATTERN_TAXONOMY.md`; search DAD for duplicates,
   broader patterns, and prior negative cases before proposing a signature.
4. Route with `subagents.yaml` and `routines.yaml`: deterministic or low effort
   first, medium for semantic grouping and grading, high only after a novel
   high-leverage candidate is evidenced, and x-high only for exceptional
   cross-repository or sovereignty architecture.
5. Require positive signals, suppressors, cooldown, wake condition, coverage,
   false-positive harm, privacy class, action boundary, validator, and rollback.
6. Emit candidate projections and recommendations. Never infer source truth or
   mutate Git, tasks, calendars, messages, repositories, or global settings.
7. Record accept, reject, dismiss, snooze, usefulness, harm, and miss feedback
   against the exact signature revision. Improve only after comparable evidence.

## Portfolio boundary

Populate only rebuildable candidate Scrum/Kanban projections. Deterministic code
owns Git facts, fingerprints, reviewed-signature matching, suppression,
cooldowns, projection rebuilds, cycle/reachability calculations, feedback
capture, historical replay, and arithmetic. Agents own ambiguous identity,
missing-edge proposals, counterexamples, research-state interpretation, novel
patterns, and bounded workflow design.

Keep ideas, workstreams, execution leases, and tasks separate. A neglected-work
signal includes activity evidence, owner/next-action gaps, dependencies, and a
quiet option; age alone is insufficient. A human confirms subjective relations
and approves every side effect.

## Output

Return coverage, matched and novel signatures, dedupe decisions, candidate
actions, model/effort rationale, board/dependency effects, validation and
feedback fields, suppressions, unknowns, evaluation status, and human gates.
