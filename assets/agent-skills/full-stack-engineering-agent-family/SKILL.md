# Full-Stack Engineering Agent Family

Deliver the smallest maintainable end-to-end software change across any stack while preserving repository contracts, security boundaries, validation, and rollback.

## Route Through DAD

1. Run DAD preflight and load `registry/agent-family-portfolio-registry.json`.
2. Use the registry triggers and `asset-dir agent-families route` to confirm this is the smallest applicable family; record excluded families.
3. Compose DAD's existing work router, hierarchical mesh, manifest-graph engineering, research intake, evaluation, and learning surfaces. Do not create a competing router, graph, lifecycle engine, research pipeline, or cockpit.
4. Resolve Luna, Terra, and Sol as current capability tiers from tools, context, privacy, cost, and consequence. Treat provider/model IDs as expiring attempt metadata only.
5. Keep one writer and a distinct independent checker. Use the role pack in `subagents.yaml` with delegation depth one.
6. Emit assignment, evidence, challenge, health, candidate-change, and human-decision records through the shared portfolio contracts. Generated relationships and health findings remain candidate evidence.
7. Run DAD midflight on material dependency, data-flow, authority, privacy, schema, runtime, acceptance, or risk drift; close with independent validation and postflight.

## Domain Contract

- Inventory the actual stack, versions, entrypoints, contracts, data flows, deployment path, and tests before proposing specialists.
- Choose framework and language adapters from current repository evidence; never make them part of stable role identity.
- Keep platform/SRE, documentation/DevEx, migration, performance, and cost optimization as specialist packs until the promotion criteria in the portfolio registry are met.
- Route every material implementation through the quality family; add security or data families only when their triggers or consequence boundary applies.

Stop on unknown source authority, an unsupported destructive migration, missing rollback for a material release, or a stack choice based only on popularity.

## Authority

The source repository owns architecture and release decisions. This family may implement only an approved bounded change and cannot deploy, install, migrate production data, or approve its own output.
